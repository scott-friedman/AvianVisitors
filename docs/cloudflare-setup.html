1 The four pieces

Three resources plus one built-in helper. Each has a boring real-world job.

Worker the brain

A little program that runs on Cloudflare's servers. Three jobs: (1) receive each detection from the Pi and write it to the ledger, (2) answer the website's "what birds lately?", (3) produce the e-ink picture on request.

name avian-worker  ·  routes /api/detection, /api/recent, /frame.png

D1 the ledger

A real SQL database (not a toy key-value store — birds can chirp more than 1,000×/day, which the cheap option won't allow free). Every detection is one row: species, time, confidence.

name avian-detections  ·  tables detections, frame_cache

Pages the website

The collage website itself — just static files (the page + the 498 illustrations). Cloudflare serves them fast from everywhere. Only re-published when the design changes.

name avianvisitors  ·  url avianvisitors.pages.dev

Browser Rendering the camera

A headless browser the Worker drives to screenshot the collage at 800×480 for the frame. The Pi can't run a browser, so this does it in the cloud. Free: 10 min/day — we use seconds.

binding BROWSER  ·  re-shoots only when the birds change

2 What happens when a robin chirps

The path from your dad's backyard to the website and the frame.

  1. BirdNET on the Pi recognizes the robin and writes it to its own log. The forwarder notices the new line and POSTs it to the Worker (with a secret password so only your Pi can).
  2. The Worker writes {robin, 07:48, 91%} into the D1 ledger.
  3. Anyone with the website open is asking the Worker "what's new?" every few seconds — it sees the robin and pops it into the collage. Live within ~5–10 seconds.
  4. Separately, the Pi's frame client asks the Worker for frame.png (now hourly). The Worker checks "did the birds change since last time?" If yes, the camera screenshots the collage; if no, it returns the saved picture instantly. The Pi shrinks it to 7 colours and shows it on the panel.

3 How it was set up

All of this was provisioned with Cloudflare's command-line tool (wrangler), signed in as you. The config lives in the repo at worker/wrangler.toml; nothing here is shared with your foobos project.

  1. Made the ledger. Created the D1 database avian-detections and set up its tables (the detections table, then later a one-row frame_cache for the e-ink picture).
  2. Set two secret passwords. AVIAN_INGEST_SECRET (so only your Pi can report birds) and FRAME_KEY (so only your Pi can trigger a frame render). Stored on Cloudflare and on the Pi — never in the code.
  3. Deployed the brain. Published the Worker, which connects to the ledger, the camera (Browser Rendering), and knows the website's address.
  4. Published the website. Bundled the collage page + 498 illustrations and pushed them to Pages.
  5. Pointed the website at the brain. The page reads its live data from the Worker's /api.
# the actual commands, for reference
npx wrangler d1 migrations apply avian-detections --remote   # build the ledger
echo <secret> | npx wrangler secret put AVIAN_INGEST_SECRET   # Pi's report password
echo <secret> | npx wrangler secret put FRAME_KEY             # Pi's frame password
npx wrangler deploy                                          # publish the brain
npx wrangler pages deploy _site --project-name=avianvisitors # publish the website
One thing still optional (Phase 5): right now deploys are run by hand from your Mac. A scoped API token from you would let GitHub auto-deploy whenever the code changes — and it'd be locked to only bird's resources, unable to touch foobos.

4 What it costs

$0 — all on Cloudflare's free tier. The only metered piece is the frame camera (10 free minutes of browser time per day); because we only re-shoot when the birds actually change, real usage is a few seconds a day. Your account is shared with foobos, so those free allowances are pooled — bird's share is a rounding error.
