## Overview (plain English)

This turns a Raspberry Pi into a "bird visitors" display. A USB mic listens 24/7; BirdNET (machine-learning audio ID) recognizes nearby birds, and they appear as a live, growing collage of illustrated birds — on a public web page **and** on an e-ink picture frame (the headline output). The Pi lives at Scott's dad's house in Sudbury, MA, so it does as little as possible: it just **listens, reports each bird to the cloud, and downloads a finished picture for the frame.** The website and the heavy image work run on Cloudflare, not the Pi.

## Decided architecture (THIS deployment — read first)

We do **not** run stock AvianVisitors (which serves the collage from the Pi via Caddy/PHP). Instead the Pi only detects, and everything public runs on **Cloudflare**, mirroring the patterns Scott already uses in the `foobos`/`sandbag` project (Pages + Worker + D1 + GitHub Actions) — but with **its own separate resources** (see "Cloudflare resources").

**Three lanes, different speeds:**

```
                 ┌─ 🟢 LIVE DATA (~5–10 s) ────────────────────────────────┐
 chirp → BirdNET │  on-detection hook → POST → avian-worker → D1            │
 (on the Pi,     │                                   └→ GET /api/recent ────┼→ page polls ~5–10 s
  several sec)   └─────────────────────────────────────────────────────────┘
                 ┌─ ⚪ STATIC SHELL (rare) ─────────────────────────────────┐
                 │  collage HTML/JS/CSS + 498 illustrations → Cloudflare    │
                 │  Pages, deployed only on design/code change (GH Action)  │
                 └─────────────────────────────────────────────────────────┘
                 ┌─ 🟣 E-INK (gentle, ~5 min) ─────────────────────────────┐
                 │  avian-worker renders frame.png (800×480) ← Pi pulls it  │
                 └─────────────────────────────────────────────────────────┘
```

- **Pi's entire job:** run BirdNET detection (writes its own SQLite) → on each detection, a hook **POSTs** {species, time, confidence} to `avian-worker` → and **pulls** `frame.png` for the panel every 5 minutes (the panel redraws only on change). All **outbound** — no open ports, no public serving from the Pi.
- **Live data freshness:** the page polls the Worker every ~5–10 s. That matches BirdNET's own latency floor (it analyses multi-second audio windows; slower on a Zero 2 W → ~5–15 s chirp-to-ID), so polling is the bottleneck-free sweet spot. SSE/WebSocket push is possible later but is overkill given the ML floor.
- **Why this shape:** kills the Zero 2 W's blockers — no local browser needed (render off-Pi), no public traffic hitting the Pi (edge serves it), frees RAM (no Caddy/PHP), and nothing inbound at the relative's house. It also sidesteps upstream's public Worker, which **is not in this repo** (the frontend assumes one — see `apt.js` references to `caches.default` / "every CF DC").

- **Worker (`avian-worker`)**: owns `POST /api/detection` (hook ingest → D1 insert, secret-gated), `GET /api/recent` (+ stats/lifelist/timeseries — reimplement `avian/api/*.php` logic against **D1**), `POST /api/clip` (secret-gated → R2 clip upload) + `GET /api/recording` (R2 clip playback, Range/CORS), `GET /api/clips` (the clip index the play view builds its instrument from — see "The play view"), and `GET /frame.png` (Browser Rendering → screenshot the Pages collage → output **800×480 7-color** for the 7.3" panel).
- **Clip retention is two-tier (since 2026-07-03; `CLIP-RETENTION-PLAN.md`)**: `clips/<basename>` expires via the bucket's 7-day lifecycle rule (prefix-scoped, set in the dashboard not the repo), but `ingest()` also keeps each species' **25 clearest clips** in `rare/<basename>` — no lifecycle rule, kept forever (≤1.1 MB/species ceiling). Since 2026-11-11 this is best-25, not first-25: once full, a new clip replaces the weakest archived one only if it beats it by `RARE_MARGIN`; the archive's contents are read from R2 (`listRareClips`, by the clip-name prefix), not D1, and `archiveRareClip` is the ONLY code allowed to delete under `rare/` (it writes before it deletes, one object per ingest). `/api/recording` reads `clips/` then falls back to `rare/` (and, for `?sci=`, to the species' oldest clip). A once-ever Veery keeps its recording; the 5000th wren doesn't pile up. Mojo is excluded (his cron self-heals from `master/`). Never put a lifecycle rule on `rare/` or `master/`.
- **Worker timezone is DST-correct via `TZ_NAME = "America/New_York"`** (computed per-hour with `Intl` in `tzOffsetHours()`; `TZ_OFFSET_HOURS` is only the fallback) — don't reintroduce fixed-offset math; the old static `-4` would have skewed every displayed time by 1 h each November. **Historic rows need the offset in force at THEIR ts, not today's** (found 2026-11-11: after the fall-back every summer time read 1 h early — the Veery clip is named `09:21:12`, the API said `08:21:12`). Format any stored `ts` with `localSql(env)` (`tz('ts')` / `tz('MAX(ts)')` inside the handlers → a literal-only `ts + CASE …` built from the zone's DST table), never `datetime(ts,'unixepoch', tzMod)`; `tzOffsetHours`/`localDayStart` stay correct for "now"/"today" only.
- **D1 (`avian-detections`)**: detection rows. Use **D1, not KV** — KV's free tier is ~1k writes/day, too few for per-detection writes; D1's write limits are generous.

## The play view (bird-call instrument) — `avian/frontend/{sampler-core,instrument,songbook}.js`

The fifth tab ("play", `#play`, view index 4) turns the box's **own recordings** into an instrument: a keyboard where every key is a real note a real bird sang into the mic, a songbook that lays tunes onto whatever notes the birds have, and a pad per species that plays its call. Built 2026-11-22. Rules that are the point of the feature (Scott's, not negotiable without him):

- **Real recordings only** — notes are cut from R2 `rare/` (+ a solo bird's recent `clips/`), never from the xeno-canto `assets/songs/`. That is the opposite choice from the song signatures, on purpose.
- **True sounds only** — no synthesis, no time-stretch, no re-pitching. Two liberties, both Scott's: "fine-tune" (a note is played ≤ ±50 cents fast/slow so it lands on its key — `playbackRate`, under 3 %, and the switch turns even that off), and, since he first heard it (2026-11-22), **the steady background around a call is turned down** when a note is cut (`cleanDb`, 12 dB: hiss, hum, rumble; turned down, never removed, and a bin that stands clear of its own floor is not touched). The voice pads and "▶ the recording" stay exactly as the microphone caught them. Don't add pitch-shifting, autotune, reverb, EQ or layering to "improve" a tune.
- **A note has to still sound like a bird** (Scott, by ear, 2026-11-22: the first version's ~0.14 s slices had "proper notes" but had stopped being bird calls). So the default cut is **"sings on"** (`sing`): the note starts on pitch at its body, then the recording carries on through the rest of that bird's call (to `z1`), a step behind the note; a held key keeps singing until it is let go. The older cuts are still on the switch: `whole` ("one call" = one syllable), `balanced` (the on-the-note body), `note` (steady part only). **Noise that comes and goes is not processed, it is not used:** a call is not followed into a rustle or a slam, a note with a racket over it is marked down (`bg`) and above `bgMax` dropped.
- **Variety matters** — flock mode spreads keys across species, but only among notes within `pickBand` of the key's best ("variety never costs quality"). Solo mode is one bird across its own range.
- **Songbook is public-domain tunes only** (`songbook.js`). Don't add a melody that is still in copyright; a visitor can type or drop in their own.

How it works, in one breath: `GET /api/clips` (worker) lists each species' archived clips → the page downloads them a few at a time through `/api/recording`, decodes to 32 kHz mono, and `sampler-core.js` (in a Web Worker) finds the notes: STFT → per-bin noise floor → ridge tracking → harmonic stacking (incl. a missing fundamental) → steady stretches (≥ 48 ms within 110 cents) → score → how far the call sings on after each note (`z1`) → 16-bit sample cuts with the steady background turned down (`cleanSlice`, from the same STFT's call/background map). `rankNotes` adds trust (does this bird hit that pitch in its other clips?), `buildKeys` assigns a singer per key, `fitMelody` slides a tune by whole semitones to where the birds have its notes. Results are cached per clip in IndexedDB (`avian-play`), so a return visit downloads nothing. Nothing loads until the tab is first opened.

Things that will bite:

- **Bump `VERSION` in `sampler-core.js` whenever `analyzeClip`'s or `cutClip`'s output changes** (it is 2 since the sings-on cut) — it keys the IndexedDB cache; without a bump, visitors keep the old analysis for 45 days. (Changes to `rankNotes`/`buildKeys`/`fitMelody` need no bump: they run on every load.)
- **The Web Worker is started from the `sampler-core.js` `<script>` tag's own URL**, so it inherits the `?v=<hash>` cache-stamp from `build-site.sh`. If you load the engine some other way, the worker would run a day-old cached copy next to a fresh page (see the Pages caching gotcha below). `build-site.sh` and its fixture test cover the three files.
- **Frontend URLs stay relative** here too (the `/birds/` proxy); the API base comes from `config.js`.
- **`instrument.js` only talks to `apt.js` through `window.AvianApp`** (set at the end of apt.js) and exposes `window.AvianPlay.show/hide`; audio goes through apt.js's single-player coordinator (`audioClaim`), so a modal recording and the instrument never play over each other.
- The e-ink screenshot (`html.frame`) never initialises the play view.

**What the stand-in clips could not tell us (learned from the real ones, 2026-11-22).** The engine was first tuned on synthetic clips and then run over 359 real recordings from all 63 confirmed species. Five findings, each now a rule in the code — keep them if you retune:

1. **Half the yard sings above C8 (4.2 kHz), where the ear no longer hears a tune.** An unweighted fit put Ode to Joy at 7 kHz: every note "correct", no melody audible. `melodic()` weighs where a tune sits; the keyboard itself still shows every real note.
2. **A hum at 300–400 Hz is often louder than a high note riding over it.** Playback's rumble cut is a 24 dB/oct high-pass at `rumbleCut(hz)` (0.45 × the note, ≤ 3.5 kHz), and a note's purity is judged over the band that survives it — one definition shared by the engine and the page.
3. **A note must LEAD.** A note sung under a louder neighbour — or under a steady drone (tree frogs, a compressor), which the denoising hides from the analysis but not from the tape — measures fine and plays back as the other sound's pitch. The engine compares the note's strongest partial with the strongest *other* peak on the raw spectrum and requires `leadBy` (2× = 3 dB). This one rule took the real-clip tunes from "a few sour notes" to none.
4. **Steady on paper is not a tone.** A wren's burble, a bunting's buzz and a turkey's gobble hold a ridge within 110 cents but are trills around it. `tone` (share of a partial's energy within ±1 bin vs ±4) marks them down; they stay playable.
5. **The clip is named for one bird, but others are on it.** A dove cooing behind a phoebe gets credited to the phoebe. A note heard in one clip only and > `oddSemis` outside what the bird sings in two or more clips is flagged `odd`: last choice for a key, left out of the solo board, labelled "may be a neighbour" on the page. It is a heuristic, not an ID.

Measured on those real clips with 3 clips per bird and with 8: ~52–58 playable keys (A3–D9), ~51 of 63 species contribute notes (trillers and quackers such as junco, mallard, teal have none and appear only as voice pads), and all 27 songbook tunes fit every note and render within 35 cents of pitch. Solo mode is only as tuneful as the bird: clean whistlers (kinglet, white-throat, titmouse) hold a tune, rough callers (turkey, red-bellied woodpecker) approximate one — the picker lists the clearest singers first.

**What the first listen changed, and what the real clips taught the second time (2026-11-22).** "Sings on" and the background clean-up were built on stand-in clips and then run, in the browser on the live site, over the 161 real recordings the page loads by default. The first cut left 40 of the 53 keys exactly as short as before. Four more rules, same standing as the five above:

6. **"Is the bird still calling?" cannot be a loudness question.** A whistle is often no louder than the hiss across the whole band; it only stands out in its own few bins. A gate at "4 × the clip's quiet level" threw most calls away. Calling is judged on the ridges (`liveOwn`, `liveMax`).
7. **A loud, close bird lifts the whole band.** Its overtones, its echo and the mp3's own noise raise every bin while it calls, so "the whole band jumped at once" (the frame's median over its floor, `gain[t]`) fires on the clearest recordings in the archive — a jay, a cardinal, a titmouse 20 dB over a quiet yard — and the first cut both stopped following them and turned them down as "noise". **Background is only what is ALWAYS there**: a bin is judged against its own floor (`loudK`), never against the frame's average. What comes and goes is handled by selection (rule in the list above), not by processing.
8. **Judge a slice the way its key plays it: above the rumble cut.** What follows a note, what counts as noise taking over, and how loud the note and its tail are (`rms`, `tail`, via `heardAbove`) are all measured above `rumbleCut(hz)`. Otherwise a dove under a kinglet "sings on" for the kinglet, and a hum under a note makes it play quieter.
9. **The note must stay in front of its own call.** Checked by rendering all 28 songbook tunes offline from the real notes and asking, at each of 1,059 note starts, whether the written pitch is the strongest thing sounding. Out of the box "sings on" lost quick tunes (Für Elise 86 %). What it took (`SING` in `instrument.js`): the rest of the call drops back the moment the body ends (no pad, 35 ms), to 0.45 of the note's level however loud the call is (a faint note before a shout was buried by its own tail); a tune note is at full level only for its written length and rings on half as long again (80–300 ms); a tapped key gets 0.6 s. With those: the written pitch leads at 99.3 % of note starts in "sings on" against 99.2 % in "balanced", and by ≥ 3 dB at 98.6 % against 99.2 %.

After the retune, on those 161 clips: still 53 keys (A3–D9) from 34 different birds; **39 of the 53 carry on into the bird's call** (13 before the retune), a key's slice is 0.64 s at the median (0.14 s in the first version, up to 1.7 s); the 14 that do not are birds that call once and stop (a goose's honk, a nuthatch's yank). Noise left around a note after the clean-up: 11 dB under the note at the median, level with it at worst. Analysis plus cutting is ~90 ms a clip on a laptop (37 before: the clean-up is a second STFT over each slice); the cached notes for those clips are ~17 MB (7 before).

**Testing.** `node --test avian/tests/sampler-core.test.mjs` (synthetic signals; in CI) covers the engine and the music logic. The cloud sandbox cannot reach `avian-worker` (proxy 403), so the real-recording bench was run *in a browser on the live site*: `eval` the branch's `sampler-core.js` into the page, fetch clips via `/api/species` + `/api/recording`, analyse, and mix tunes offline to measure them. ## Night screens and the owl watch (built 2026-11-26)

**Night screens.** When the frame's window holds no birds, `/frame.png` no longer shows "no birds heard in this window" all night. It renders one of four screens drawn by `avian/frontend/night.js` (`?night=recap|star|sky|owl`, data from `GET /api/night`): **recap** "Today in the yard", **star** "Bird of the day" (only when one earned it: first ever and sure, back after ≥ 7 days, or < 20 calls in the 30 days before — `starReason`), **sky** "The yard is asleep" (real moon, today's birds as silhouettes), **owl** "Heard tonight" (only when something called ≥ 40 min after sunset). Which one is `nightPlan` in `worker/src/night.js` (pure, unit-tested): midday lull → recap; evening → hourly rotation recap → star → sky, with owl every other slot when something called, counted from when the yard went quiet; from 23:00 until the first bird → hold on owl if anything called, else sky. Night screens are laid out at `FRAME_NIGHT_SIZE` (748×403, the mat's visible window) and the Pi places them 1:1 (no autocrop; `X-Frame-Kind: night`). **The Pi now asks `GET /api/frame-sig` whether to redraw** (its old species-hash check never changed overnight, so it would never have seen a rotation). Knobs in `worker/wrangler.toml` comments.

**Why no owls (found 2026-11-25).** BirdNET-Pi's location filter (eBird-based species-occurrence model) calls even Barred and Great Horned Owls "not expected in Sudbury" — owls are under-reported because owling is done at night. In 4 days the box dropped 6 Barred Owl calls up to 0.96 and 3 Great Horned up to 0.83. Fix: `~/BirdNET-Pi/whitelist_species_list.txt` (gitignored, lives on the Pi) listing the five local owls bypasses the filter (`scripts/utils/analysis.py`). **Owl watch.** `scripts/utils/owlwatch.py` keeps every owl-genus guess ≥ `OWLWATCH_MIN` (0.3, birdnet.conf) that BirdNET did not keep: a ±1.5 s clip in `~/BirdSongs/OwlWatch/<date>/` and a line in `~/BirdSongs/owl_watch.txt` (max one per species per 5 min). ## Live view of the frame (the panel mirror, built 2026-11-26)

The menu's "picture frame" section shows **what the panel is actually showing**, above the shared time-window picker. After each successful redraw `frame/display.py` copies the driver's own quantised buffer (`panel_mirror.snapshot_device`, read before `dev.show()`, kept only once show() returns) and `panel_mirror.publish_pending` uploads it to `POST /api/frame-confirmed` (FRAME_KEY in `X-Frame-Key`, sha256 + display time + `X-Frame-Kind`/`X-Frame-Screen`, which `/frame.png` now sends). D1 `panel_mirror` (migration 0008, one row, only moves forward); the page reads `GET /api/frame-mirror` (JSON) + `GET /api/frame-mirror.png?v=<sha>` every 60 s while the menu is open. **Never fall back to a render**: a picture that was rendered but not shown (quiet hours, a refused stale frame, the Pi offline) must not appear here; "since <time>" is the honest signal. A failed upload is retried each timer tick and can never stop the panel. `mirror = false` in the Pi's config turns it off. Shows nothing until the panel's first redraw after the Pi is updated.

## Conventions & gotchas

- **License CC-BY-NC-SA-4.0 (non-commercial)** — don't propose commercial use.
- **No mic ⇒ no detections** — the #1 failure mode.
- **Confirmed vs unconfirmed species (since 2026-11-11)** — a species is *confirmed* once it has a detection ≥ `CONFIRM_CONF` (0.9) or detections on two local days (`confirmedSql()` / `justConfirmed()` in the worker). Unconfirmed species stay on the life list with an "unconfirmed" label (atlas card + modal), are left out of the `/api/coverage` gap lists, and do **not** fire the coverage webhook — it fires on the detection that confirms the species, not on first sight. Don't commission art for an unconfirmed one-off.
- **Detected ≠ shown** — the collage renders only species that have illustration art (`avian/assets/illustrations/<sci>.png`). A detected bird with **no art** still logs to D1 and appears in stats/lifelist, but is **invisible in the collage**. The bundled 249-species set skews boreal and **misses common eastern-MA backyard birds** (Cardinal, Blue Jay, Chickadee, Titmouse, Red-bellied Woodpecker, Grackle, Carolina Wren, Catbird, E. Bluebird, WT Sparrow). **The exact gap (46 land species, ranked by Sudbury detection frequency) + per-bird progress is tracked in `SUDBURY-ART-TODO.md`** (derived from the BirdNET range model; pipeline `pregen.py` → `avian/scripts/keycut.py` (NOT `cutout.py` — its onnxruntime hangs on this Mac) → rebuild → redeploy). Add art via the `avian/scripts/` Gemini pipeline → rebuild → redeploy Pages — fully decoupled from the Pi (past detections render retroactively). Gotcha: Cloudflare Pages serves a **200 HTML fallback** for a missing `.png`, so probe art by `content-type`/local file, not HTTP status.
- **Song signatures are a build-time Pages artifact** — the modal "song signature" bloom is a *canonical* per-species fingerprint precomputed from a clean **xeno-canto** song by `avian/scripts/build-signatures.mjs` (Node+ffmpeg) → `avian/assets/signatures.json` + bundled `avian/assets/songs/<slug>.mp3` (tap-to-play). NOT extracted from our noisy R2 clips. Re-run to expand coverage (incremental; `--force`/`--only`). The shared STFT lives in `avian/frontend/spectral-core.js` (browser + the build script both use it). Needs the xeno-canto v3 key at `~/.config/avian/xeno-canto-key` (600). **DSP rule learned 2026-06-21: compute energy/pitch from LINEAR POWER, never the dB grid** (dB summed over a linear-frequency band pins every dominant near the ceiling). Full story: `SPECTRO-CONCEPTS-PLAN.md`. Two more traps found 2026-07-29 closing the last 3 gaps: **(a) the bloom only analyses `SPEC_FLO`–`SPEC_FHI` = 1800–8500 Hz** (songbird-tuned), so a low-voiced bird is fingerprinted on its harmonics, not its fundamental — a Mallard's ~600 Hz quack renders as the 1.8–2.6 kHz rasp pinned at the floor, and `tonality()` further docks 0.25 for a dominant ≤ `SPEC_FLO+200`. That's a floor no recording can beat; accept it or add the bird to `COVERAGE_SIG_EXEMPT` — don't go hunting for a "better" clip. **(b) the q:A→q:B fallback used to be gated on `recs.length`**, so one badly-licensed A-grade hit could mask perfectly good B recordings (Cooper's Hawk: a single `by-nc-nd` A recording hid two `by-nc-sa` B ones and it reported "no compatible-license song"). Fixed in `buildOne()` — fall back whenever q:A yields no *license-compatible* candidate. If a species skips for licensing, check q:B by hand before reaching for an override.
- **512 MB tuning is mandatory** — even *detection-only* untuned OOM-thrashes the Zero 2 W unreachable (RAM, not CPU, is the bottleneck). The real fixes are **swap (zram) + numba cache hygiene + clearing the StreamData backlog**, not stripping services. Applied by `pi/zero2w-tune.sh`; see `PI-RECOVERY.md`.
- **BirdNET-Pi's stock 95%-disk purge silently no-ops on the lean box** (found 2026-07-03): `scripts/disk_check.sh` hard-exits unless the web-UI-created `scripts/disk_check_exclude.txt` exists — and lean-mode stripped the web UI. Meanwhile `~/BirdSongs/Extracted` grows ~420 MB/day (mp3 + spectrogram PNG per detection) → SD full in ~8 months with the heartbeat still green. Fixed: `pi/prune-extracted.sh` + `avian-prune.timer` (daily, deletes `By_Date` day-dirs >30 days by NAME) and `pi/update.sh` creates the exclude file as a backstop. See `pi/README.md` → "Disk prune".
- **D1, not KV**, for detection writes (KV free tier ≈ 1k writes/day).
- **Separate from foobos** — never reference foobos resource IDs in this repo's `wrangler.toml`; same account, but pooled free-tier quotas.
- **BirdNET latency floor** (~5–15 s on a Zero 2 W) is why ~5–10 s polling is sufficient — don't over-engineer push.
- **Frame geometry is ported to the 7.3" panel** — `frame/display.py` is 800×480 7-color (`PANEL_W/H`, `INKY7`); only `frame/hardware/` CAD remains 13.3".
- **Pi is outbound-only** — it pushes detections and pulls `frame.png`; it must not be made to serve the public site.
- **D1 planner full-scan trap (bit us 2026-07-03)** — windowed `GROUP BY sci` / `COUNT(DISTINCT sci)` queries choose `idx_detections_dedupe` and scan the WHOLE detections table unless pinned with `INDEXED BY idx_detections_ts`; at 16k rows + the 30-s `refreshAll()` poll that hit ~108M D1 rows read/day and reset-looped D1's storage object (multi-minute 500 bursts on every endpoint → dropped detections, heartbeat flaps). Fixes live in `worker/src/index.js`: index pins on the mis-planned queries, an isolate-memory **poll micro-cache** for the 9 polled read endpoints (keyed on params + `MAX(ts)` + 5-min bucket; a new detection busts it instantly; `X-Poll-Cache: hit` header for probing), and dispatch-level retries on transient `D1_ERROR …reset` (all routes idempotent; `/frame.png` excluded — a retry would double-bill Browser Rendering). New windowed aggregate queries must verify their plan (`EXPLAIN QUERY PLAN … --remote`) and join the cache set if polled.
